# spiffe-mcp-lab

A lab wiring four things that rarely meet in one stack:

- **Workload identity** — SPIFFE/SPIRE, trust domain `spiffe://ai-agent.id.eviden.internal`
- **User identity** — OAuth 2.1 / OIDC via Keycloak (the only real AS here)
- **An MCP server** — Spring Boot resource server with proper audience discipline
- **A real PKI** — EJBCA issuing a name-constrained intermediate above SPIRE

The point: an AI agent workload calls an MCP server with a token that proves **which human** it acts for (`sub`) *and* **which workload** it is (`act.sub` = SPIFFE ID), bridged exclusively by RFC 8693 token exchange, with the workload authenticating to Keycloak using **only its JWT-SVID** (`draft-ietf-oauth-spiffe-client-auth`) — no client secrets anywhere.

> SPIFFE answers *which workload*. OIDC answers *on behalf of which human*. Never substitute one for the other.

Not a WIMSE implementation.

## Layout

```
infra/                # SPIRE, EJBCA, compose, acceptance.sh   [C — human-led]
mcp-server/           # Spring Boot resource server            [A]
keycloak-spiffe-spi/  # ClientAuthenticator fallback (M0b)     [B]
agent-client/         # SVID → token exchange → MCP call
specs/                # Pinned truth. Read-only. fetch-specs.sh populates.
docs/                 # ARCHITECTURE · SPEC-REGISTRY · BUILD-PLAN · CONVENTIONS · DECISIONS · VERSIONS
```

Start with `docs/ARCHITECTURE.md` (topology, the three-trust-store table), then `docs/BUILD-PLAN.md` (milestones M0–M9, each with an executable exit criterion). All version pins live in `docs/VERSIONS.md`; all resolved questions live in `docs/DECISIONS.md`.

Done means `./infra/acceptance.sh` exits 0: the happy path **plus all four rejections** (no client cert, wrong audience, JWT-SVID as bearer, unlisted SPIFFE ID).

## Launching the stack on a fresh machine

Nothing needs to be copied from an old machine except this repository. Every
gitignored artifact (SPIRE bootstrap certs, the EJBCA hierarchy, the RA
keystore, docker volumes, the Ollama model) is machine-local by design and is
regenerated by the scripts below — a new machine becomes a new lab instance
with its own root CA, which is intended.

### 1. Install prerequisites

- **Docker Desktop** with compose v2 (on Windows: WSL2 backend, the default).
- **bash** — Git Bash on Windows (ships with Git for Windows); any shell on Linux/macOS.
- Nothing else. Java and the Angular console are built inside the Docker images
  (D-024); no JDK, Node, or Angular CLI on the host.

Check: `docker compose version` and `bash --version` both answer.

### 2. Get the code

```bash
git clone <repo-url> spiffe-mcp-lab
cd spiffe-mcp-lab
```

On Windows, clone into a path **without special characters** (`&` in a path
breaks npm's cmd shims if you ever build the console on the host). Do not copy
docker volumes or `infra/pki/` contents from another machine.

### 3. Build and launch (one command block, run from the repo root)

```bash
# one-time gitignored artifacts (never leave a machine)
bash infra/spire/gen-bootstrap.sh        # node-attestation bootstrap CA
bash infra/pki/setup-ejbca.sh            # EJBCA hierarchy + name-constrained intermediate (minutes)
bash infra/pki/setup-employee-profile.sh # M12: employee profiles + cert-service's RA credential

# everything else: image builds (incl. console), services, SPIRE registrations,
# Keycloak realm (incl. two-hop delegation), demo + pki profiles, model pull
bash demo/reset.sh --full
```

First run is the slowest: all image builds plus the ~2–3 GB Ollama model
download. Subsequent `reset.sh --full` runs take ~3 minutes.

### 4. Hosts file (once, for browser demos)

The browser resolves the Keycloak issuer by its in-network name. Add this line:

- Windows: `C:\Windows\System32\drivers\etc\hosts` (edit as Administrator)
- Linux/macOS: `/etc/hosts`

```
127.0.0.1 keycloak
```

### 5. Verify before trusting it

```bash
bash demo/checklist.sh --full     # clock skew FIRST, health, model, full acceptance
```

Per-milestone checks live in `scripts/` (`check-m2.sh` … `check-m13.sh`,
`check-scope-intersection.sh`); the terminal gate is `./infra/acceptance.sh`
(exit 0 = happy path + every rejection enforced). The two-hop delegation story
is `scripts/check-m12.sh` (real certificate through the nested act chain) and
`scripts/check-m13.sh` (off-table audience/scope/depth all refused).

### 6. Use it

Open **http://localhost:8090** and log in as `alice` / `alice-password`.
The login page offers two consent variants (with and without the optional
`mcp:audit` scope) — what alice grants at the consent screen is exactly what
the agent may do. Ask the chat to onboard an employee to see the two-hop chain
issue a real certificate.

Other surfaces: Keycloak admin at http://localhost:8080 (`admin`/`admin`),
EJBCA admin at https://localhost:8444/ejbca/adminweb/ (client-cert gated).

### Day-to-day operation

| Task | Command |
|---|---|
| Stage recovery (app layer restart + idempotent re-setup) | `bash demo/reset.sh --soft` (~90 s) |
| Deterministic full restart, volumes kept | `bash demo/reset.sh --full` (~3 min) |
| Destroy SPIRE/EJBCA state and rebuild from nothing | `bash demo/reset.sh --cold` (asks first; re-runs the PKI setup) |
| Stop everything | `cd infra && docker compose --profile demo --profile pki down` |
| Rebuild one service after a code change | `cd infra && docker compose --profile demo build <name> && docker compose --profile demo up -d <name>` |
| Console UI iteration without image rebuilds | `npm run build` in `console/`, then agent-web with the `infra/docker-compose.dev.yml` overlay |

Note: raw `docker compose up` starts nothing PKI-related unless you pass
`--profile pki` — EJBCA lives behind that profile; `reset.sh` handles it.

### If something fails

1. **Any JWT/token failure:** check container clock skew before touching code —
   `demo/checklist.sh` does this first for a reason.
2. **Cross-container TLS failure:** two hypotheses maximum, then
   `openssl s_client -showcerts` and read the actual chain (CLAUDE.md §8).
3. **Issuance fails with "RA credential missing":** run
   `bash infra/pki/setup-employee-profile.sh` (it is idempotent).
4. After restarting `cert-service` manually, restart `agent-pki` too — its MCP
   session to cert-service dies with the container (D-032).
